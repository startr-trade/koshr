# v0.1.0

_Released 2026-11-28._

## What shipped

### FEAT-002 — Rust workspace skeleton under MIT OR Apache-2.0

koshr has a buildable Rust workspace licensed MIT OR Apache-2.0, so every later item has a home

- THE SYSTEM SHALL build and test with `cargo build --workspace` and `cargo test --workspace` on the toolchain pinned in rust-toolchain.toml
- THE SYSTEM SHALL declare `MIT OR Apache-2.0` in every crate manifest and ship both licence texts
- THE SYSTEM SHALL check text files out with LF line endings on every OS

### FEAT-003 — Brand assets and README with the light/dark lockup

koshr presents itself with the family's brand and a README that says what it is and how to start

- THE SYSTEM SHALL show the koshr lockup through a `<picture>` element with dark and light sources
- THE SYSTEM SHALL ship the mark, both lockups, favicon, app icon and social preview under assets/brand
- WHEN the assets are made, THE SYSTEM SHALL have its brand assets checked against the family brand guide

### FEAT-004 — Community files: CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, CONTRIBUTORS

Contributors know how to contribute, report a vulnerability and behave in the koshr project

- THE SYSTEM SHALL carry CONTRIBUTING.md, SECURITY.md, CODE_OF_CONDUCT.md and CONTRIBUTORS at the repository root, linked from the README, with no email address in CONTRIBUTORS
- THE SYSTEM SHALL carry CHANGELOG.md with an `## [Unreleased]` heading

### FEAT-005 — mdBook user guide

koshr has a user guide that is built and checked with every change

- WHEN a change lands on main, THE SYSTEM SHALL build the book and fail on a broken internal link
- THE SYSTEM SHALL describe every command the released binary offers

### FEAT-006 — make ci and GitHub Actions per the Rust CI practices

koshr's local `make ci` runs exactly what its GitHub Actions run, so CI fails only on what the machine could not check

- THE SYSTEM SHALL run the same fmt, clippy, cross-target clippy and test steps as the CI workflow, cheapest first
- THE SYSTEM SHALL pin one toolchain version in rust-toolchain.toml and in every workflow
- THE SYSTEM SHALL pin every action to a full commit SHA and every runner image to a version
- WHEN a pull request is opened, THE SYSTEM SHALL run fmt, clippy and tests on Linux, macOS and Windows with fail-fast off
- THE SYSTEM SHALL pass actionlint over every workflow
- THE SYSTEM SHALL build every crate, tests included, with no C compiler available
- THE SYSTEM SHALL check advisories, licences and sources of every dependency with cargo-deny

### FEAT-007 — Release workflow and Koshr 0.1.0 on crates.io

koshr 0.1.0 is published on crates.io from a release workflow that publishes only after CI is green on the tagged commit

- WHEN koshr is run with `--version`, THE SYSTEM SHALL print `koshr` and its version and exit 0
- WHEN koshr is run with `--help`, THE SYSTEM SHALL list its commands and exit 0
- WHEN a tag is pushed, THE SYSTEM SHALL refuse to build until CI has succeeded on the tagged commit
- WHEN 0.1.0 is cut, THE SYSTEM SHALL be installable with `cargo install koshr`

### MNT-001 — Agent-neutral from the start: Koshr speaks of agents, with Claude Code as one adapter

koshr's product text speaks of agents and the person, and names an agent framework only in that framework's adapter files, so contributors using any agent are at home

- THE SYSTEM SHALL continue to name no agent vendor in product text outside the adapter files
- THE SYSTEM SHALL state the agent-neutral wording rule in CONTRIBUTING.md
