# v0.1.0

_Released 2026-11-28._

The first release of koshr. It claims the name and sets up the project; it does not do anything useful with git yet.

koshr is a git-compatible, self-hostable code store with signed, verified history. It is a tool, not a service.

## What is in this release

- **The `koshr` binary.** `koshr --version` and `koshr --help`, and nothing else yet.
- **How to get it.** `cargo install koshr`, or a release archive for Linux (x86_64 and arm64, static), macOS (Intel and Apple silicon) or Windows (x86_64). Each archive has a SHA-256 file beside it, and each release carries a build attestation and a bill of materials.
- **A user guide** at `docs/guide`, built with mdBook: what koshr is, installing, and the commands.
- **Project files.** MIT OR Apache-2.0 licences, CONTRIBUTING, SECURITY, a code of conduct and this changelog.

## For contributors

- One Cargo workspace, with the Rust toolchain pinned.
- `make ci` runs locally what CI runs on GitHub: format, lint, dependency checks, cross-platform lint and the tests. CI runs on Linux, macOS and Windows.
- The build uses no C compiler, and a check proves it.
- A release is published only after CI has passed on the tagged commit.
- Product text says "agent" and "the person" and names no agent vendor; a check keeps it so.

## What comes next

The verify gate: `koshr verify` lets any git server, or a CI check on a hosted one, refuse commits that are not signed by a key bound to a live Sigillr identity, and `koshr merge` merges a pull request as a signed commit of your own.

## Not verified in this release

Two checks can only be read after this release's tag is pushed: that the release workflow refuses a commit without green CI, and that `cargo install koshr` installs a binary that answers `--version`.
